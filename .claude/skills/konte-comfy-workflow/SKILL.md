Fix the ComfyUI adapter files konte ships in its templates after `bun run sync:comfy-adapters` re-emits one — the file comes back with a `// @generated` marker and a fresh `source-hash`, and all prior hand-edits are gone.

The cleanup procedure is the one shipped into user projects — follow it from there:

@../../../src/cli/templates/workspace/dot.agents/skills/konte-comfy-workflow/SKILL.md

With these overrides:

- **`adapters/comfy/` means `src/cli/templates/workspace/adapters/comfy/`** throughout. Glob those and fix the ones carrying `// @generated`.
- **Skip the import step (Step 1)** — the file is regenerated by the sync script. Start at 2.1, diffing the regenerated file against the last committed version (`git diff` / `git show HEAD:`) to reconstruct the prior hand-edits.
- **The prompt guide is not a sibling `.md`** (overrides 2.6's guide half): a bundled adapter's guide lives at `src/cli/templates/workspace/dot.konte/guides/<model>.md`, and grouped variants list a shared file before their own, so the `guide` field an adapter carries is the mapping — restore it from the diff like any other hand edit. The `.md` itself is never regenerated; update it only if the workflow's prompting changed. See `prompt-guide-authoring`.
- **`allowedIn` has no scaffold here** — the import path comments one in, the sync path does not. Restore it from the diff.
- **Verify with `bun run check`** (overrides 2.9) — it runs `check:templates`, which regenerates `mod.ts` and type-checks every template.
